# Cap 中文试用版的后续维护

## 普通用户

- 用新的 **中文版安装包** 覆盖安装到原目录，`profile` 不会被安装程序覆盖，卸载也会保留它。
- 开始菜单的“维护与迁移”可以导出 / 导入数据，并手动检查官方稳定版本。
- 官方有更新，不等于中文版已经适配完成。当前没有远程中文版更新源，不会偷偷安装官方版或后台升级。
- 迁移工具只打包当前 `profile`，自定义外部录屏目录、外部素材和操作系统授权需另行处理。

## 维护者：从新官方版本生成中文版

安装包和免安装包中保留源码补丁、词表、汉化脚本与此流程；单独的 maintenance.zip 不含个人数据。

1. 根据 maintenance.zip 的 `source.json` 从官方仓库获取原始源码，以及对应版本的 GPUI 框架源码和官方补丁。完整修改由原始 Git 版本 + `source-changes.patch` + `tools/zh-cn` 还原。
2. 在已有官方 Git 仓库上运行 `prepare-update.ps1`，传入官方标签、新目录、GPUI 目录和上一版补丁。脚本新建独立的 Git worktree，不会重置当前中文版工作区。
3. 框架版本改变或补丁冲突时停下来人工处理，不自动发布半成品。即使补丁成功应用，也必须审阅 `zh-cn-review.txt`，补充新文案和人工汉化点。
4. 根据新版本官方构建说明准备媒体依赖。Windows 当前构建需要 Rust MSVC、Visual Studio C++ 工具、Node，以及官方依赖准备脚本。使用 `local-chinese-trial` feature，确保 `Cargo.toml` 与 `release.json` 的版本一致。
5. 当前版本使用的构建方式：

```powershell
cd <新源码目录>\apps\desktop-gpui
cargo +1.95.0-x86_64-pc-windows-msvc rustc --release --target x86_64-pc-windows-msvc --features local-chinese-trial --bin cap-gpui --jobs 6 -- -Ccodegen-units=16
```

Rust / 框架 / FFmpeg 等版本需随新官方版本调整，不保证上面工具链可永久沿用。

6. 用 `package-trial.ps1` 整理对应版本的免安装目录，可用 `-OfficialDirectory` 指定新官方版的程序目录。`cap-muxer.exe` 必须来自相同官方版本，不能直接沿用旧版。运行 `build-installer.ps1`，可传入 `-PackageDirectory`、`-CompilerPath`、`-CrtDirectory`、`-GpuiDirectory` 和 `-OutputDirectory`；构建脚本只打包程序和默认配置，不读取现有 profile。两个打包脚本使用 PowerShell 7 运行；安装后的迁移工具兼容 Windows 自带的 PowerShell 5.1。
7. 检查实际录制界面、菜单、提示、编辑与导出；测试覆盖升级后数据保留、迁移恢复和卸载保留数据。确认后再分发新中文版安装包。脚本不会提交、推送、签名或自动上传发布。

`prepare-update.ps1` 调用示例（版本号请使用实际存在的官方标签）：

```powershell
.\prepare-update.ps1 -Ref cap-v0.6.1 -RepositoryPath <官方源码仓库> -Destination <新的适配目录> -GpuiDirectory <匹配的GPUI源码目录> -PatchPath <上一版source-changes.patch> -CnRevision 3
```

## 打包工具

当前使用 Inno Setup 6.4.3。中文安装界面来自该版本官方源码仓库的 `Files/Languages/Unofficial/ChineseSimplified.isl`，保留原维护者署名。程序和安装包未签名；不要关闭系统安全功能来安装来源不明的二次打包文件。
